기준일: 2026-11-18 / 양식: T04

2026-11-18 통합: Codex 세션(`c:\dev\ncc-vbr(codex)`)에서 더한 C-CIFS-21·22를 옮겨 적었다. 근거 기록은 [docs/history/codex-2026-11-17](../history/codex-2026-11-17/cifs/01-analysis-and-design.md)에 있다.

## 3. 그대로 유지한 특이 동작

| 번호 | 동작 | 그대로 둔 이유 |
|---|---|---|
| K-CIFS-01 | 원본에서 지워진 파일은 대상에 남는다. 동기화가 아니라 누적 백업이다 | 원본의 목적이다 |
| K-CIFS-02 | 복사할 때 수정 시각과 권한을 옮기지 않는다. 대상의 수정 시각은 복사한 때다 | 변경 판단(원본 수정 시각 > 대상 수정 시각)이 이 동작에 기대고 있다 |
| K-CIFS-03 | 원본 파일이 기준 시각 이후 건드려지지 않았으면, 대상의 크기가 달라도 다시 복사하지 않는다 | 원본의 성능 설계다(1.2). 대상이 손상돼도 복구되지 않으므로 운영자가 알아야 한다. 기준 시각 파일을 지우면 전체를 비교한다. 2.068부터는 `Full Scan Day` 요일에도 전체를 비교한다(C-CIFS-21) |
| K-CIFS-04 | 이전 버전 파일은 이름이 `.zip`이지만 형식은 gzip이다 | `vbr_remove`와 운영자가 이 이름에 기대고 있다. 풀 때는 `gzip -dc`를 쓴다 |
| K-CIFS-05 | 제외 목록은 최상위와 2단계 분할 디렉터리 바로 아래에서만 비교한다. 더 깊은 디렉터리는 제외할 수 없다 | 원본 동작이다 |
| K-CIFS-06 | 기준 시각 파일 이름을 만들 때 경로의 첫 글자를 버린다. 절대 경로를 전제로 한 규칙이라 상대 경로를 주면 이름이 이상해진다(`src` → `rc`) | 원본이 만든 파일을 이어받으려면 이름이 같아야 한다 |
| K-CIFS-07 | 이전 버전 보관에 실패해도 새 내용을 복사한다 | 원본 동작이다. 실패는 오류로 센다(C-CIFS-08) |
| K-CIFS-08 | 백그라운드 실행 때 `umask(0)`이라 파일이 0666으로 만들어진다 | 원본 동작이다(Q-05) |

현행 분석서 10장의 K-CIFS-01~05에 구현하면서 확인한 06~08을 더했다.

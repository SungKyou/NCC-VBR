# cifs 전환 계획과 운영 안내

기준일: 2026-11-17 / 양식: T07 / 상태: 초안. 시험 환경에서 절차를 실행하기 전이다.

## 1. 전환 전제

- [ ] 검증 판정이 "운영 전환 가능"이다. 현재는 "개발 검증 통과"다([06-test-report.md](06-test-report.md)).
- [ ] 결정 대기 항목 Q-01~Q-05, Q-08~Q-11이 정해졌다([00-process/04-open-decisions.md](../00-process/04-open-decisions.md)).
- [ ] 이 문서의 설치·되돌리기 절차를 시험 서버에서 한 번 실행했다.

## 2. 배포물

| 파일 | 설치 위치 | 비고 |
|---|---|---|
| `go/bin/linux-amd64/vbr_cifs` | 원본 `vbr_cifs`가 있던 디렉터리 | `go/build.ps1 linux` 또는 `go/build.sh linux`로 만든다. 외부 라이브러리가 필요 없다(zlib 포함) |
| `node_info.cfg` | 그대로 | 바꿀 항목 없음. 2단계 분할 설정이 이제 적용되므로 `2ND SEARCH DIR` 값을 확인한다(Q-01) |

실행 파일은 x86-64 Linux용이다. Go 1.26으로 만든 실행 파일이 운영 서버의 커널 버전에서 실행되는지 설치 전에 `./vbr_cifs -version`으로 확인한다. 운영 서버의 CentOS 버전과 커널 버전을 받지 못해 이 확인은 하지 못했다.

## 3. 설치 절차

1. 원본 실행 파일을 보관한다. `cp -p vbr_cifs vbr_cifs.c-2.0672`
2. 실행 중인 백업이 없는지 확인한다. `ps -ef | grep vbr_cifs`
3. 새 실행 파일을 놓고 실행 권한을 준다. `cp vbr_cifs.go vbr_cifs && chmod 755 vbr_cifs`
4. 버전을 확인한다. `./vbr_cifs -version` → `NCC-VBR CIFS Manager version = 3.0000`

`history` 디렉터리와 대상 디렉터리는 그대로 둔다. 전환본은 원본이 만든 기준 시각 파일을 이어받는다(T-CIFS-P18).

## 4. 병행 운영

| 항목 | 내용 |
|---|---|
| 기간 | 사용자가 정한다. 권장은 백업 주기 3회 이상, 그 사이에 파일 변경이 있는 날을 포함 |
| 방법 | 원본은 운영 대상에 그대로 실행한다. 전환본은 별도 작업 디렉터리에서 같은 원본 디렉터리를 별도 대상 디렉터리로 백업한다. 두 프로그램이 같은 대상에 동시에 쓰지 않게 한다 |
| 비교 항목 | `server.log`의 `Total File` 줄 숫자, `diff -r 대상A 대상B`(이전 버전 파일은 이름의 시각만 다름) |
| 통과 기준 | 파일 내용이 같다. 숫자 차이는 변경 대장의 항목으로 설명된다 |

병행 운영에서 차이가 날 수 있는 경우

- 두 실행 사이에 원본 파일이 바뀌면 복사한 내용이 다르다. 프로그램 차이가 아니다.
- 접근 시각이 기준 시각 판단에 들어간다. 먼저 실행한 프로그램이 파일을 읽으면서 접근 시각이 바뀌어, 나중에 실행한 프로그램이 더 많은 파일을 비교할 수 있다. 복사 결과에는 영향이 없다.
- `2ND SEARCH DIR`이 설정되어 있으면 작업 단위와 로그의 작업 수가 다르다(C-CIFS-02).

별도 대상 디렉터리를 둘 공간이 없으면 병행 운영 대신 T-CIFS-I02(시험 서버 비교)를 운영 자료의 일부로 실행한다.

## 5. 교체 절차

1. 3장의 설치 절차를 운영 서버에서 실행한다.
2. 다음 백업 주기의 `server.log`에서 `ver 3.0000 start`와 `backup finished`, `Error = [0]`을 확인한다.
3. `transaction.log`에 시작·종료·합계 세 줄이 있는지 확인한다.
4. 포털에 완료 이벤트가 들어왔는지 확인한다.

## 6. 되돌리기

| 되돌리는 조건 | 절차 | 되돌린 뒤 확인할 것 |
|---|---|---|
| 전환본이 시작하지 않는다(커널·권한 문제) | `cp -p vbr_cifs.c-2.0672 vbr_cifs` | 다음 주기의 `server.log` |
| 합계나 결과 파일이 원본과 다르고 변경 대장으로 설명되지 않는다 | 같음. 증거(두 로그, 차이 나는 파일)를 보관한다 | 같음 |
| 실행 시간이 받아들일 수 없게 길다 | 같음 | 같음 |

전환본이 만든 기준 시각 파일과 대상 디렉터리는 원본이 그대로 이어받는다(T-CIFS-P19). 되돌리기 전에 따로 할 일은 없다.

한 가지 주의할 점이 있다. 전환본은 오류가 있었던 실행에서 기준 시각을 갱신하지 않는다(C-CIFS-06). 그 상태에서 원본으로 되돌리면 원본은 오래된 기준 시각부터 다시 비교한다. 결과는 맞고 시간만 더 걸린다.

## 7. 운영자가 알아야 할 달라진 점

| 항목 | 전 | 후 |
|---|---|---|
| 실행 방법 | `vbr_cifs 원본 대상 번호` | 같다. 옵션 `-home`, `-config`, `-foreground`를 쓸 수 있다 |
| 시작 시간 | 작업자 수만큼 초 단위로 늦게 시작 | 바로 시작 |
| 대상이 없을 때 | 모든 파일에서 오류를 내며 끝까지 진행 | 시작하지 않고 `Target directory … is not valid` 로그 |
| 합계 로그 | `Total File = […], …, Create dir = […]` | 끝에 `, Error = [n]`이 붙는다 |
| 오류가 있었던 실행 | 기준 시각 갱신 | 기준 시각을 그대로 둔다. 로그에 `Backup history file … is not updated. error count = [n]` |
| 2단계 분할 설정 | 적용되지 않음 | 적용됨 |
| 메시지 큐 | 실행 중 `ipcs -q`에 전용 큐가 보임 | 쓰지 않는다 |
| 종료 신호 | 바로 종료 | 하던 파일까지 처리하고 종료. 기준 시각은 갱신하지 않음 |
| 필요한 라이브러리 | zlib, pthread | 없음 |

## 8. 실행 방법

```sh
# 원본과 같은 방식. 실행 디렉터리의 node_info.cfg, history/, server.log 를 쓴다.
cd /vbr && ./vbr_cifs /nas/source /backup/target 20261117090503001

# 작업 디렉터리를 따로 지정한다.
./vbr_cifs -home /vbr /nas/source /backup/target 20261117090503001

# 백그라운드로 분리하지 않는다. 끝날 때까지 기다리고 종료 코드를 받는다.
./vbr_cifs -foreground /nas/source /backup/target 20261117090503001; echo $?
```

전체 비교를 다시 시키려면 해당 쌍의 기준 시각 파일(`history/…vbr`)을 지우고 실행한다.

이전 버전 파일을 복원하려면 다음과 같이 한다.

```sh
gzip -dc < '보고서.xlsx-vbr-20261117090503.zip' > '보고서.xlsx.복원'
```

## 9. 문제가 생겼을 때

| 증상 | 확인할 것 | 조치 |
|---|---|---|
| 실행했는데 `server.log`에 아무것도 없다 | 실행한 디렉터리가 맞는가(로그는 실행 디렉터리 또는 `-home`에 쓰인다) | 올바른 디렉터리에서 실행 |
| `Target directory … is not valid` | NAS 대상이 마운트되어 있는가 | 마운트 후 다시 실행 |
| `Directory […] is not valid` | 원본 디렉터리가 마운트되어 있고 읽을 수 있는가 | 같음 |
| `Error = [n]`이 0이 아니다 | 같은 로그의 `file processing error`, `directory prepare error` 줄 | 원인(권한, 공간, 이름 충돌)을 없앤 뒤 다시 실행. 기준 시각이 갱신되지 않았으므로 다음 실행이 다시 처리한다 |
| 매번 실행 시간이 길다 | `is not updated. error count` 로그가 계속 나오는가 | 계속 실패하는 파일을 해결한다 |
| 포털에 이벤트가 없다 | `Send to VBR WEB Portal failed` 로그, 설정의 포털 주소 | 주소와 방화벽 확인 |
| 설정이 적용되지 않는다 | 로그의 `Special backup policy … setup` 줄 | 섹션명 `[VBR Manager]`와 키 철자 확인 |

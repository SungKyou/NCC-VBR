# vbr_vm 요건 정의서

기준일: 2026-11-19 / 유형: B 재설계 / 기준: `vbr_agent` 3.000 기능(F-VM-01~10, [02](02-baseline-reference-analysis.md) 1장), ncc-xen 규약(02 13장), 2026-11-19 사용자 지시 1~12([00](00-charter.md) 2장) / 작성: Claude Code

## 1. 목적과 범위

- 이 서비스가 하는 일: 호출자(관리 서버, 나중에 middle 서비스)가 JSON으로 보낸 요청을 받아 XenServer 풀의 VM을 XVA 파일로 백업하고, XVA 파일을 VM으로 복구하고, XVA 파일을 검증한다. XenServer에는 XAPI로 원격 접속한다.
- 범위에 드는 것: 전체 백업, 디스크 선택 백업, 복구, XVA 검증, 작업 상태 조회, 취소, 결과 보고(설정 시), 토큰 인증, 암호 보관, 설정 즉시 반영, 다국어 문구, 데모·시험 스크립트
- 범위에 들지 않는 것: dom0 상태 점검, 풀·VM 현황 조회(지시 10), OVF/OVA, XenServer 이벤트 전송(ncc-xen 규약 3), 남은 스냅샷 자동 정리(Q-A17과 같음), 기존 `vbr_agent`·cifs·remove 변경(지시 1·2)

## 2. 이해관계자와 사용 방식

| 누가 | 어떻게 쓰는가 |
|---|---|
| 관리 서버 / middle 서비스(나중) | `POST /api/v1/jobs`로 작업을 맡기고, 조회 API로 결과를 받거나 결과 보고를 받는다 |
| 시험자 | `demo.ps1`로 요청·조회·취소를 하고 PASS/FAIL을 본다 |
| 운영자 | `sysconfig.yaml`을 고쳐 바로 반영한다. 로그와 작업 기록으로 상태를 본다 |
| XenServer 풀 | XAPI(443)로 스냅샷·내보내기·가져오기를 받는다 |

## 5. 제약과 가정

| 번호 | 내용 | 종류 | 확인 상태 |
|---|---|---|---|
| 1 | 백업 파일 경로는 이 서비스가 도는 서버에서 접근할 수 있어야 한다(NFS 마운트 등) | 제약 | ncc-xen과 같음 |
| 2 | XenServer는 zstd XVA를 직접 가져오지 못한다. zstd 백업은 이 서비스로만 복구할 수 있고 XenCenter로는 못 한다 | 제약 | ncc-xen 17.8 실기 |
| 3 | 원본 VM이 같은 풀에 있으면 MAC 보존 복구는 거부된다 | 제약 | 실기 E-01 |
| 4 | 같은 백업 파일을 같은 풀에 MAC 보존으로 두 번 복구할 수 없다(uuid 중복) | 가정 | 미확인(E-02에서 추정) |
| 5 | 요청마다 XAPI에 로그인한다. 동시 작업 수가 작아(기본 3) 세션 부담은 작다 | 가정 | 1단계와 같은 방식 |
| 6 | 1단계 `vbr_agent`와 같은 서버에서 포트를 달리해 함께 돌 수 있다 | 제약 | DEC-VM-02 |

## 6. 유지할 것과 바꿀 것

| 구분 | 내용 |
|---|---|
| 반드시 유지 | 외부 시스템에 일어나는 일: 임시 스냅샷을 만들고 지운다, 원본은 건드리지 않는다, 덜 받은 파일은 완성본 이름이 되지 않는다, 복구 결과 VM은 일반 VM이다, XAPI 오류 원문을 그대로 전한다 |
| 바꿔도 되는 것 | 요청·응답 형식, 결과 문장, 설정 형식, 로그 형식, 조회 방식 |
| 바꿔야 하는 것 | 실패해도 조회 코드가 0인 것(K-AG-01) → 상태 `failed`. 처리 중 취소 불가 → 가능 |

## 7. 용어

| 용어 | 뜻 |
|---|---|
| 작업(task) | 요청 하나. `taskId`로 구분한다 |
| 디스크 번호 | VBD의 `userdevice`(0, 1, …). 기존 15자리 자리값의 자리 순서와 같다 |
| 결과 보고 | ncc-xen 규약 2. 이 서비스가 결과를 호출자에게 보내는 것 |
| 기존 서비스 | 1단계 `vbr_agent` 3.000 |

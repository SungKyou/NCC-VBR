# cifs 인터페이스 명세

기준일: 2026-11-17 / 양식: T05

밖에서 보이는 접점의 기준 문서다. "원본과의 차이"가 "없음"인 항목은 전환본이 원본과 같아야 한다.

## 1. 목록

| 번호 | 종류 | 이름 | 방향 | 상대 |
|---|---|---|---|---|
| IF-CIFS-01 | 명령행 | `vbr_cifs` | 입력 | 호출자 |
| IF-CIFS-02 | 설정 파일 | `node_info.cfg`의 `[VBR Manager]` | 입력 | 운영자 |
| IF-CIFS-03 | 파일 | 기준 시각 파일 `history/*.vbr` | 입력·출력 | 자기 자신(다음 실행) |
| IF-CIFS-04 | 파일 | 이전 버전 파일 `*-vbr-YYYYMMDDHHMMSS.zip` | 출력 | 운영자, `vbr_remove` |
| IF-CIFS-05 | 파일 | `server.log` | 출력 | 운영자 |

## 2. 명령행 (IF-CIFS-01)

```
vbr_cifs [-home dir] [-config file] [-foreground] source-dir target-dir seq-no
vbr_cifs -version
```

| 인자 | 뜻 | 필수 | 검사 | 원본과의 차이 |
|---|---|---|---|---|
| `source-dir` | 원본 디렉터리 | 예 | 열 수 없으면 종료 | 없음 |
| `target-dir` | 대상 디렉터리 | 예 | 없으면 종료 | 원본은 검사하지 않음(C-CIFS-10) |
| `seq-no` | 작업 번호. 앞 17자가 완료 이벤트 메시지에 들어간다 | 예 | 없음 | 없음 |
| `-version`, `-ver` | 버전 출력 | | | 버전 값이 다름(C-CIFS-20) |
| `-home`, `-config`, `-foreground`(`-fg`) | 작업 디렉터리, 설정 파일, 백그라운드 분리 안 함 | 아니오 | | 원본에 없음(C-CIFS-15) |

옵션은 위치 인자보다 앞에 둔다. 인자 개수가 맞지 않으면 사용법을 화면과 `server.log`에 쓰고 255로 끝낸다.

원본은 인자에 공백이 있으면 첫 단어만 읽는다(`sscanf %s`). 전환본은 인자를 그대로 쓴다. 공백이 든 최상위 경로는 원본에서 동작하지 않던 경우라 호환 문제가 없다.

## 3. 설정 (IF-CIFS-02)

파일 형식은 [common/03-config-spec.md](../common/03-config-spec.md)에 있다. 섹션은 `[VBR Manager]`다.

| 키 | 형식 | 기본값 | 뜻 | 원본과의 차이 |
|---|---|---|---|---|
| `MAX Log size` | 정수(byte) | 50000000 | 로그 파일 교체 기준 | 없음 |
| `MAX Thread cnt` | 정수 | 50 | 작업자 수. 50보다 크면 50 | 1보다 작으면 1로 한다(원본은 작업자가 없어 작업이 처리되지 않음) |
| `2ND SEARCH DIR` | 전체 경로를 공백으로 구분. 최대 200개 | 없음 | 2단계 분할 디렉터리 | 원본은 동작하지 않음(C-CIFS-02) |
| `EXCLUSION DIR` | 전체 경로를 공백으로 구분. 최대 200개 | 없음 | 백업 제외 디렉터리 | 줄 길이 제한 없음(C-CIFS-03), 끝 구분자 무시(C-CIFS-17) |
| `WEB server(IP)` | 주소 | 없음 | 포털 주소. 없으면 이벤트를 보내지 않는다 | 없음 |
| `WEB server(PORT)` | 정수 | 없음 | 포털 포트 | 없음 |

목록이 200개를 넘으면 원본과 같이 그 기능을 끄고 로그를 남긴다. 경로에 공백이 있는 디렉터리는 목록에 넣을 수 없다(원본과 같다).

## 4. 파일

### 기준 시각 파일 (IF-CIFS-03)

- 경로: `<작업 디렉터리>/history/<원본>-<대상>.vbr`
- 이름 규칙: 원본 경로와 대상 경로 각각에서 `/`를 `_`로 바꾸고 첫 글자를 버린다.
  예: 원본 `/nas/src`, 대상 `/backup/tgt` → `history/nas_src-backup_tgt.vbr`
- 읽는 시점: 시작할 때. 첫 줄의 첫 단어를 정수로 읽는다. 파일이 없으면 0이다.
- 쓰는 시점: 오류 없이 끝났을 때. 이번 실행의 시작 시각을 쓴다.
- 형식:

```
<시작 시각의 Unix 초> [YYYY-MM-DD HH:MM:SS]
```

- 예:

```
1794888173 [2026-11-17 13:02:53]
```

- 원본과의 차이: 디렉터리가 없으면 만든다(C-CIFS-07). 오류가 있었으면 쓰지 않는다(C-CIFS-06). Windows에서는 `\`와 `:`도 `_`로 바꾼다(C-CIFS-12). 형식과 이름은 같다. 원본과 전환본이 서로의 파일을 이어받는 것을 시험으로 확인했다(T-CIFS-P18, P19).

### 이전 버전 파일 (IF-CIFS-04)

- 경로: `<대상 파일 경로>-vbr-YYYYMMDDHHMMSS.zip`. 시각은 보관하는 때의 현지 시각이다.
- 형식: gzip. 압축 수준 5. 이름은 `.zip`이지만 zip 형식이 아니다(K-CIFS-04).
- 내용: 덮어쓰기 직전의 대상 파일 내용 전체.
- 푸는 방법: `gzip -dc < 파일 > 복원할이름`
- 원본과의 차이: 없음. 압축 결과의 byte는 압축 라이브러리가 달라 같지 않을 수 있으나 풀어낸 내용은 같다(T-CIFS-P10).

### server.log (IF-CIFS-05)

- 경로: `<작업 디렉터리>/server.log`
- 형식: `[YYYY-MM-DD HH:MM:SS]메시지`. 메시지가 여러 줄이면 둘째 줄부터는 시각이 없다.
- 교체: 쓴 뒤 크기가 `MAX Log size`를 넘으면 `server.log.old`로 이름을 바꾼다. 이전 `.old`는 덮어쓴다.
- 주요 문구(원본과 같다):

```
[2026-11-17 13:02:53]VBR CIFS backup start.  source dir = [<원본>], target dir = [<대상>]
[2026-11-17 13:02:53]Backup base time  = [<기준 시각>]
[2026-11-17 13:02:53]Backup start time = [<시작 시각>]
[2026-11-17 13:02:53]BEGIN : <시작 시각> [YYYY-MM-DD HH:MM:SS]
[2026-11-17 13:02:53]END : <시작 시각> [YYYY-MM-DD HH:MM:SS]
[2026-11-17 13:02:53]VBR CIFS backup finished.  source dir = [<원본>], target dir = [<대상>]
[2026-11-17 13:02:53]Total File = [n], Total Dir = [n], Change file = [n], Create dir = [n], Error = [n]
```

- 원본과의 차이: 합계 줄 끝의 `, Error = [n]`, 줄 순서 일부, 안내 문구 일부(C-CIFS-19). 실제 출력 예는 `docs/evidence/cli-windows.txt`에 있다.

### transaction.log (IF-CIFS-06)

- 경로: `<작업 디렉터리>/transaction.log`
- 형식: NUL 문자(0x00) 하나 + `[YYYY-MM-DD HH:MM:SS:mmm]메시지` + 줄바꿈. `mmm`은 밀리초다.
- 한 번 실행에 세 줄을 쓴다(시작, 종료, 합계).

```
\0[2026-11-17 13:02:53:120]VBR CIFS backup start.   source dir = [<원본>], target dir = [<대상>]
\0[2026-11-17 13:02:53:480]VBR CIFS backup finished : source dir = [<원본>], target dir = [<대상>]
\0[2026-11-17 13:02:53:480]Total File = [n], Total Dir = [n], Change file = [n], Create dir = [n], Error = [n]
```

- 교체: `server.log`와 같다(`transaction.log.old`).
- 원본과의 차이: 합계 줄 끝의 `, Error = [n]`.

## 5. 통신 전문 (IF-CIFS-07)

### 완료 이벤트

- 상대: WEB 포털. 설정의 주소와 포트로 TCP 접속한다.
- 연결 방식: 이벤트마다 접속, 송신, 응답 한 번 수신, 닫기. 접속 5초, 송수신 3초 제한.
- 문자: ASCII. 경로에 한글이 있으면 UTF-8 byte로 들어간다.

| 순서 | 필드 | 길이 | 형식 | 값 |
|---|---|---|---|---|
| 1 | 길이 | 7 | 10진수, 앞을 0으로 채움 | 2~7번 필드의 byte 수 합계 |
| 2 | msg_type | 1 | 문자 | `B` |
| 3 | msg_seq | 17 | 숫자 | 송신 시각 `YYYYMMDDHHMMSS` + `001` |
| 4 | task_type | 1 | 문자 | `0` |
| 5 | timeout | 3 | 숫자 | `000` |
| 6 | priority | 1 | 문자 | `1` |
| 7 | msg_text | 가변 | JSON | 아래 |

```json
{"event_info":[{"event_type":"N","host_name":"VBR CIFS","host_uuid":"NONE","event_time":"2026-11-17 09:05:03","event_code":"CIFSFIN00","event_msg":"20261117090503001 BACKUP: /src => /tgt Finished."}]}
```

전문 전체의 예(한 줄이다. 길이 필드 `0000223`은 뒤따르는 223 byte를 뜻한다):

```
0000223B2026111709050300100001{"event_info":[{"event_type":"N","host_name":"VBR CIFS","host_uuid":"NONE","event_time":"2026-11-17 09:05:03","event_code":"CIFSFIN00","event_msg":"20261117090503001 BACKUP: /src => /tgt Finished."}]}
```

- 응답: 포털이 보낸 내용을 최대 4,999 byte까지 읽어 `server.log`에 쓴다. 내용을 해석하지 않는다.
- 원본과의 차이: 제한 시간, 연결 닫기, JSON 문자열 값의 `"`와 `\` 이스케이프(C-CIFS-09). 필드 배치와 값은 같다. 원본은 전문을 구조체 메모리에서 문자열 길이로 잘라 보내는데, 그 결과가 위 표와 같다는 것은 소스로 확인했다(`vbr_cifs.c:1117~1134`). 실제 포털과의 송수신은 확인하지 못했다(T-CIFS-I03).

## 7. 종료 코드와 화면 출력 (IF-CIFS-08)

| 코드 | 뜻 | 원본과의 차이 |
|---|---|---|
| 0 | 정상. 버전 출력. 백그라운드 분리에 성공한 부모 | 없음 |
| 1 | 시작 실패, 대상·원본 디렉터리 오류, 중단 | 원본은 255 또는 1 |
| 2 | 끝까지 처리했으나 오류가 있음 | 원본은 0 |
| 255 | 인자 오류 | 없음 |

백그라운드로 분리되면 호출자가 받는 값은 원본과 같이 부모의 0(또는 인자 오류의 255)뿐이다. 1과 2는 `-foreground`로 실행할 때만 호출자에게 보인다.

화면 출력은 버전과 사용법뿐이다.

| 항목 | 내용 | 원본과의 차이 |
|---|---|---|
| 디렉터리 구조 | 원본 디렉터리와 같은 상대 경로 | 없음 |
| 파일 내용 | 원본 파일과 같음 | 없음 |
| 파일 수정 시각 | 복사한 때 | 없음 |
| 파일 권한 | 백그라운드 실행 때 0666, 디렉터리 0755(마운트 옵션이 우선) | 없음 |
| 복사하지 않는 것 | 스냅샷 디렉터리, 제외 디렉터리, 심볼릭 링크 등 일반 파일·디렉터리가 아닌 것 | 없음 |
| 빈 디렉터리 | 만든다 | 없음 |

# 배치 교체와 운영 검증 절차

이번 교체·롤백 절차는 CIFS와 Remove에 적용한다. XenServer dom0 Agent의 전환 여부는 두 배치의 전환 이후 결정한다.

## 인계에 필요한 자료

- 기존 바이너리, 빌드 스크립트·컴파일러 버전, 실행 계정, 스케줄러의 전체 호출 인자, 작업 디렉터리, 실제 설정 키 목록을 기록한다.
- Linux에서 실제 배포 대상 아키텍처를 확인한다. CIFS 원본과 대상 모두 공유 정체성·읽기/쓰기 권한·마운트 옵션을 기록한다. 디렉터리 존재 확인만으로 마운트 상태를 판정하지 않는다.
- 개발 `node_info.cfg`는 별도 보관한다. 새 파일이나 섹션이 필요하면 키·단위·기본값·시험 값의 위치를 기록한다.
- 대상 이력 파일, `history/*.vbr`, 복구 가능한 NAS 스냅샷/시험 사본을 보존한다. 포털 이벤트 수신과 실제 백업 결과는 따로 확인한다.

## 시험과 교체

| 순서 | 작업 | 증거 |
|---|---|---|
| 1 | Go 빌드로 기존 비교본을 보존한다. 원본과 변경본은 격리된 동일 입력에서 실행한다. | OS, 버전, 실행 인자, 종료 코드 |
| 2 | CIFS는 첫 실행·증분·`dis_`와 오류 후 재실행을 비교한다. | 상대경로 목록, 해시, 이전 버전 gzip 복원, 로그, 상태 시각 |
| 3 | Remove는 LOG 모드에서 두 실행의 후보 경로 집합을 비교한다. | 기간 기준 시각, 변경된 후보와 이유, 원본 파일 훼손 없음 |
| 4 | 시험 공유에서 작업 손상과 파일/디렉터리 경쟁, 마운트 단절, 포털 불가를 재현한다. | 삭제·덮어쓰기·이력·재시도 판정, 도달해야 하는 오류 |
| 5 | 원본 스케줄러를 중지하고 실행 중 작업이 없는 것을 확인한 뒤 소규모 업무부터 교체한다. | 실행 주체 하나 확인, 첫 실행·다음 증분·복원 증거 |
| 6 | 비교 기준을 넘는 오류, 성능 악화, 대상 데이터·이력 불일치가 있으면 새 트리거를 중지한다. | 종료된 작업, 최종 상태와 NAS 보호 조치 |

되돌릴 때는 관측된 데이터 변경을 먼저 확정하고, 기존 바이너리와 설정·작업 디렉터리로 트리거를 복구한다. 기준 시각은 검증한 백업 세대에 맞춰 복구하고, 중간에 바뀐 이력·이동 데이터에 필요한 복구는 별도로 수행한다. 성능 문턱값은 두 NAS의 실측과 기존 배치 윈도우를 바탕으로 정한다.

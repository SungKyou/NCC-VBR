# remove 전환 계획과 운영 안내

기준일: 2026-11-17 / 양식: T07 / 상태: 초안. 시험 환경에서 절차를 실행하기 전이다.

## 1. 전환 전제

- [ ] 검증 판정이 "운영 전환 가능"이다. 현재는 "개발 검증 통과"다([06-test-report.md](06-test-report.md)).
- [ ] 결정 대기 항목 Q-06~Q-11이 정해졌다.
- [ ] 운영에서 쓰는 `Delete Mode` 값과 보존 일수를 확인했다.

## 2. 배포물

| 파일 | 설치 위치 | 비고 |
|---|---|---|
| `go/bin/linux-amd64/vbr_remove` | 원본 `vbr_remove`가 있던 디렉터리 | `go/build.ps1 linux`로 만든다. 외부 라이브러리가 필요 없다 |
| `node_info.cfg` | 그대로 | 바꿀 항목 없음. `QUEUE ID`는 남겨 둬도 된다(전환본은 읽지 않는다) |

## 3. 설치 절차

1. 원본 실행 파일을 보관한다. `cp -p vbr_remove vbr_remove.c-1.000`
2. 실행 중인 삭제 작업이 없는지 확인한다. `ps -ef | grep vbr_remove`
3. 새 실행 파일을 놓는다.
4. 버전을 확인한다. `./vbr_remove -version` → `File Remove (BATCH) for NCC-VBR version = 2.000`

## 4. 병행 운영

삭제 프로그램은 같은 대상에 두 번 실행하면 둘째 실행에는 지울 것이 없다. 그래서 병행 운영은 LOG 모드로 한다.

| 항목 | 내용 |
|---|---|
| 방법 | 운영의 삭제 주기 직전에, 전환본을 별도 작업 디렉터리에서 LOG 모드로 같은 디렉터리·같은 보존 일수로 실행한다. 이어서 원본을 운영 방식대로 실행한다 |
| 비교 항목 | 전환본 `delete.log`의 대상 수와 원본 `server.log` 합계의 `Delete files` 수. 운영이 LOG 모드면 두 `delete.log`를 정렬해 비교 |
| 통과 기준 | 대상 수가 같다 |
| 기간 | 삭제 주기 2회 이상 |

전환본을 먼저 실행하고 원본을 뒤에 실행하면, 그 사이 기준 시각이 조금 지나 원본 쪽 대상이 한두 건 많을 수 있다. 기준 시각 경계에 걸린 파일인지 이름의 시각으로 확인한다.

## 5. 교체 절차

1. 3장의 설치 절차를 실행한다.
2. 첫 운영 실행은 LOG 모드로 한다(`Delete Mode` 줄을 잠시 주석 처리). `delete.log`를 검토한다.
3. 문제가 없으면 `Delete Mode = DELETE`를 되돌리고 다음 주기부터 운영 방식대로 실행한다.
4. `server.log`의 `NCC-VBR batch finished`와 합계 줄의 `Error = [0]`을 확인한다.

## 6. 되돌리기

| 되돌리는 조건 | 절차 | 되돌린 뒤 확인할 것 |
|---|---|---|
| 전환본이 시작하지 않는다 | `cp -p vbr_remove.c-1.000 vbr_remove` | 다음 주기의 `server.log` |
| LOG 모드 검토에서 대상이 아닌 파일이 `delete.log`에 있다 | 같음. `delete.log`와 `server.log`를 보관한다 | 같음 |

전환본이 남기는 상태 파일은 없다. 되돌리기 전에 할 일이 없다. 다만 지운 파일은 되돌릴 수 없다. 그래서 5장 2번(첫 실행은 LOG 모드)을 건너뛰지 않는다.

## 7. 운영자가 알아야 할 달라진 점

| 항목 | 전 | 후 |
|---|---|---|
| 실행 방법 | `vbr_remove 디렉터리 일수` | 같다. 옵션 `-home`, `-config`, `-foreground`를 쓸 수 있다 |
| 잘못된 보존 일수 | 0으로 읽어 모든 이전 버전이 대상 | 실행하지 않고 사용법 출력, 종료 코드 255 |
| 메시지 큐 | 설정 `QUEUE ID`의 큐를 쓰고 끝나도 남는다 | 쓰지 않는다. 설정 항목이 필요 없다 |
| 동시 실행 | 같은 큐 키로 동시에 실행하면 작업이 섞인다 | 서로 영향이 없다. 다만 같은 작업 디렉터리에서 동시에 실행하면 `delete.log`와 `server.log`를 함께 쓴다. 작업 디렉터리를 나눈다 |
| 합계 로그 | `…Delete files = [n] Skip files = [n]` | 끝에 `, Error = [n]`이 붙는다 |
| 안내 로그 | 일부 한글 | 영문 |
| `-version` 종료 코드 | 1 | 0 |
| 시작 시간 | 작업자 수만큼 초 단위로 늦게 시작 | 바로 시작 |

## 8. 실행 방법

```sh
# 30일 지난 이전 버전 파일을 찾는다. 설정에 Delete Mode = DELETE 가 없으면 지우지 않고 delete.log 에 적는다.
cd /vbr && ./vbr_remove /backup/target 30

# 끝날 때까지 기다리고 종료 코드를 받는다.
./vbr_remove -foreground /backup/target 30; echo $?

# LOG 모드의 결과를 검토한 뒤 지운다.
wc -l delete.log && less delete.log
sh delete.log
```

## 9. 문제가 생겼을 때

| 증상 | 확인할 것 | 조치 |
|---|---|---|
| `Usage` 출력과 종료 코드 255 | 인자 개수, 보존 일수가 0 이상의 정수인가 | 인자 수정 |
| 지워지지 않는다 | `server.log`에 `LOG mode`가 있는가. 설정 섹션명과 `Delete Mode = DELETE` 철자 | 설정 수정 |
| `delete.log`가 없다 | 대상이 없으면 파일이 생기지 않는다. 합계의 `Delete files = [0]` 확인 | 정상 |
| `Error = [n]`이 0이 아니다 | `file processing error` 줄의 사유(권한, 읽기 전용 마운트) | 원인 해결 후 다시 실행 |
| 대상 수가 예상보다 적다 | 제외 디렉터리, 스냅샷 디렉터리, 이름 규칙에 맞지 않는 파일 | 인터페이스 명세 5장 확인 |

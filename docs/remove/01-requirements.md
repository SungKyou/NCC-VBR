# remove 요건 정의서

기준일: 2026-11-17 / 원본: `remove/vbr_remove.c` 1.000, `remove/bs_common.c` / 양식: T01

## 1. 목적과 범위

- 하는 일: 지정한 디렉터리 아래에서 `vbr_cifs`가 남긴 이전 버전 파일(`…-vbr-YYYYMMDDHHMMSS.zip`) 가운데 보존 일수가 지난 것을 지운다. NAS 용량을 관리하기 위한 배치다.
- 전환 범위에 드는 것: `vbr_remove` 실행 파일의 모든 동작.
- 전환 범위에 들지 않는 것: 이 프로그램을 실행하는 쪽(스케줄러로 추정), LOG 모드가 만든 `delete.log`를 실행하는 절차.

## 2. 이해관계자와 사용 방식

| 누가 | 어떻게 쓰는가 |
|---|---|
| 호출자(스케줄러 또는 운영자. 추정) | `vbr_remove 디렉터리 보존일수`를 실행한다. 바로 백그라운드로 분리된다 |
| 운영자 | LOG 모드에서 `delete.log`를 검토한 뒤 셸로 실행한다. `server.log`로 결과를 본다 |

## 5. 제약과 가정

| 번호 | 내용 | 종류 | 확인 상태 |
|---|---|---|---|
| 1 | 설정 섹션 `[File Remove (BATCH) for NCC-VBR]`은 개발 환경 `node_info.cfg`에 없다. 있는 것으로 본다 | 가정(사용자 지시 2) | 확인됨 |
| 2 | 섹션이 없으면 LOG 모드, 작업자 50개로 동작한다 | 제약(원본 기본값) | 확인됨 |
| 3 | 대상 디렉터리는 `vbr_cifs`의 대상 디렉터리다 | 가정 | 미확인 |
| 4 | 삭제 기준은 파일 이름의 시각이다. 파일의 수정 시각은 보지 않는다 | 제약(원본 동작) | 확인됨 |

## 6. 유지할 것과 바꿀 것

| 구분 | 내용 |
|---|---|
| 반드시 유지 | 명령행, 설정 키, 삭제 대상 조건, LOG 모드가 기본인 것, `delete.log` 형식 |
| 바꿔도 되는 것 | 작업 분배 수단(공유 메시지 큐) |
| 바꿔야 하는 것 | 숫자가 아닌 보존 일수를 0으로 읽어 모든 이전 버전을 지우는 것 |

## 7. 용어

| 용어 | 뜻 |
|---|---|
| 이전 버전 파일 | `vbr_cifs`가 덮어쓰기 전에 남긴 `-vbr-시각.zip` 파일 |
| 보존 일수 | 이전 버전 파일을 남겨 두는 기간. 둘째 인자 |
| 삭제 기준 시각 | 지금에서 보존 일수를 뺀 시각 |
| LOG 모드 | 지우지 않고 지울 명령만 적는 방식 |

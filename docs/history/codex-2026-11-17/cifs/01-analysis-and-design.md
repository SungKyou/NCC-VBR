# CIFS 증분 백업 요건과 전환 설계

## 업무 요건

| ID | 인수 기준 |
|---|---|
| CIFS-01 | 읽기 전용 NetApp에서 읽고 Dell EMC에 동일 상대 경로로 보관한다. 새 파일과 기존 파일 수정이 계속 반영된다. |
| CIFS-02 | 최상위 `dis_X`에 대해 백업의 `X`를 먼저 재사용한다. 원본 `X`가 남아 있거나 백업 `dis_X`에 데이터가 있으면 두 영역을 보존한다. |
| CIFS-03 | 일반 rename·이동 후보는 별도 전수 스캔 없이 수집한다. 확인이 부족하면 기존 백업과 이력을 유지하고 새 경로를 일반 백업한다. |
| CIFS-04 | 원본 삭제는 신뢰할 수 있는 최초 확인 이후 30일 이상 보존한다. 이력 버전 만료와 원본 삭제 보존을 독립적으로 계산한다. |
| CIFS-05 | 사용자 영역 1,000개 이상, 파일 약 1억 개 환경에서 전체 파일의 신규 대상 조회나 전체 목록 상주 메모리를 추가하지 않는다. |
| CIFS-06 | C 2.068에서 추가된 `Full Scan Day`에 해당하는 요일에는 증분 기준 시각 없이 파일 크기와 mtime을 비교한다. |

| `remove/vbr_remove.c file_delete:471–500`, `go_code/internal/remove/remove.go IsExpiredVersion, File` | 이름이 규칙에 맞는 이전 버전을 기간 기준으로 정리한다. 원본과 백업을 대조하는 삭제 감지나 현재 백업 본체의 자동 삭제는 없다. |

일반 rename 후 `NEW/file`이 대상에 없으면 시간 필터를 지나기 전에 복사한다. 따라서 단순 rename은 최신 트리 누락보다 `OLD` 복제본 잔존과 중복 복사를 먼저 일으킨다. 새 경로에 기존 세대의 파일이 이미 있으면 시간 필터 또는 동일 크기·mtime 비교에 의해 새 객체가 누락될 수 있다. 작업 중 읽은 옛 경로의 ENOENT와 늦게 등장한 새 경로도 한 번의 순회에서 놓칠 수 있다.

## 이번 Go 변경과 다음 안전성 보완

- 사용자 제공 C 2.068 코드의 `Full Scan Day`를 `internal/cifs/cifs.go Run, fullScanEnabled`와 `copier.go File`에 반영했다. `node_info.cfg`의 `[VBR Manager]`에서 첫 문자의 숫자(0=일요일, 6=토요일)를 읽는다. 설정이 없으면 일요일이고 개발 설정의 `2`는 화요일이다. 빈 값이나 유효하지 않은 첫 문자는 로그에 남기고 요일별 전체 비교를 적용하지 않는다. 실행 시작 시각의 로컬 요일을 사용한다.
- 전체 비교일에는 실행에 쓰는 기준 시각을 0으로 설정하고 원본 atime·mtime·ctime 필터를 생략한다. 기존 파일은 크기가 다르거나 원본 mtime이 더 최신인 경우 복사한다. 크기가 같고 원본 mtime이 대상과 같거나 더 과거인 경우에는 내용이 달라도 이 비교에서 검출되지 않는다. 대상에 없는 파일은 요일과 무관하게 복사한다. 성공 시 기준 시각 파일에는 실제 실행 시작 시각을 저장하고, 파일 처리에 오류가 있으면 기존 기준을 유지한다.
- 요일별 전체 비교는 이미 있는 대상 경로의 오래된 파일까지 비교하는 방식이다. 일반 디렉터리 rename·이동의 동일성 판정과 기존 경로 정리는 별도 설계에서 다룬다. 기존 `dis_` 우선 재사용은 두 동작과 독립적으로 수행한다.
- `internal/cifs/copier.go TopDir`에서 원본 `X`가 실제로 없을 때 기존 `renameDisabled`를 작동시킨다. 권한·네트워크 오류나 `X`의 공존은 보류하고 `dis_X`를 일반 백업한다. 일반 파일당 CIFS 조회 수는 그대로이며 `dis_` 후보마다 원본 조회를 한 번 수행한다.
- 다음 변경 후보는 `copier.File/copyFile/keepOldVersion`: 같은 대상 디렉터리 내부 임시 파일로 복사하고 쓰기·닫기·필요한 내구성 확인 이후 게시한다. 검증된 이전 버전 보관이 실패하면 기존 본체를 유지한다. 이력 충돌은 기존 이름 예약을 검증하면서 재시도 정책을 정한다. Windows 교체 방식, 기존 ACL, 모드, SMB reconnect와 flush를 NAS에서 먼저 시험한다.
- `walk.Visitor.File`에 현재 `FileInfo`를 전달하는 변경은 원본 측 중복 조회를 줄일 수 있다. 열기와 게시 사이 타입·크기·시각 재확인의 경합 검증을 먼저 한다. 기존 대상 파일별 `Lstat` 제거는 보증 가능한 매니페스트 또는 공급자 변경 피드 도입에 의존한다.

## CIFS 관찰과 후보 식별

사용자가 관찰한 SMB 3.0, `cache=strict`, `relatime` 환경에서 파일 생성과 이름 변경은 직접 부모만 갱신했고, 디렉터리 rename은 그 부모를 갱신하고 이동 객체의 mtime을 보존했다. 파일 내용 변경과 손자 변경은 조상 mtime에 의존할 수 없다. NetApp/Dell EMC에서 반복했을 때의 속성 반영 지연과 마운트 설정을 각각 기록한다. [Linux CIFS 사용 가이드](https://docs.kernel.org/5.19/admin-guide/cifs/usage.html)

- 기존 열거와 `lstat` 결과로 상대경로, mtime, Linux `dev/ino`, 유형을 얻는다. 직접 자식 수는 순회 콜백에서 센다. 제외·실패가 있으면 관측 범위를 함께 남긴다. Windows나 비 Linux에서는 ID의 출처를 명시하고 미지원이면 비활성화한다.
- mtime은 직접 자식 변경 후보의 보조 신호다. SMB File ID 또는 서버 inode는 동일 공유에서 rename·재마운트·failover·삭제 후 재사용 및 중복을 검증한다. `dev`는 클라이언트 마운트 구분에만 쓴다. 서버 공유 식별과 관측 세대를 함께 저장하고 식별 안정성이 깨지면 자동 이동을 중지한다.
- 직접 자식 수, 메타데이터 표본, 정렬된 이름·크기·mtime 지문은 후보를 좁힐 수 있다. 같은 규모와 시각의 별개 폴더를 합치지 않는다. 파일 내용 해시는 별도 읽기 비용이 있으므로 한정된 후보 검증 또는 실험에서만 쓴다.
- 사용자 영역별 로컬 저장소에 관측 세대·부모 ID·상대경로·직접 자식 집계·완결성·백업 완료 세대를 스트리밍 저장한다. 변경 후보분만 별도 분석한다. 디렉터리 순회 도중 후보를 모아도 이동 판정은 양쪽 부모 관측을 확정한 뒤 수행한다. 초기 버전은 후보만 남기며 복사 흐름을 바꾸려면 후속 실행 또는 동일 스냅샷 기반 작업 계획이 필요하다.

| 시나리오 | 판단 및 비용 |
|---|---|
| 같은 부모 rename | 부모의 직접 자식 비교와 동일 세대의 안정 ID. mtime만 일치하면 후보 기록만 한다. |
| 다른 부모 이동 | 이전·새 부모가 모두 완결되어야 한다. 공유와 사용자 경계를 넘는 자동 이동은 보류한다. |
| 다단계 폴더 rename | 최상위 일치쌍 하나로 계획하고 자손의 중복 이동을 제거한다. 하위 변경은 기본 탐색으로 처리한다. |
| 파일 삭제 / 폴더 삭제 | 직접 부모의 정상 열거 결과 및 누락 재확인 후 삭제 후보를 등록한다. 폴더는 자손에 적용되는 보존 기록을 둔다. 제외·오류·취소 영역은 해당 세대를 확정하지 않는다. |
| 이름 변경 뒤 같은 이름 재생성 | 현재 경로가 아니라 객체 세대로 분리한다. 이전 경로가 사용 중이면 자동 이동 보류. 기존 `dis_` 처리에도 공존 보호를 적용했다. |
| 다른 파일의 동일 크기와 mtime | 동일성 판단 불가. 필요시 후보 콘텐츠의 추가 검증으로 제한한다. |
| 순회 중 이동 또는 캐시 지연 | 스캔 결과가 충돌하면 해당 영역 보류. 스냅샷, 다음 완결 실행, 캐시 안정화 후 후보 재확인 중 환경에 맞는 방식을 시험한다. |

## Dell EMC 재사용과 복구

동일 공유 내 rename을 실험한다. 동일 부모·다른 부모, 같은 볼륨·다른 볼륨, 대소문자, 열린 파일·공유 잠금, 기존 대상, 파일/디렉터리 mtime·ACL, SMB I/O 카운터를 기록한다. 서버 측 메타데이터 변경이면 전송량 감소를 기대할 수 있다. 실제 복사 유무와 원자성은 Dell EMC 구성별 시험 결과로 남긴다.

자동 이동 관문은 동일 공유·동일 사용자, 이전과 새 원본 관측의 일치, 이전 백업 세대 완결, 대상 부재의 서버 측 보장, 외부 쓰기 배제, 복구 탐색의 이전 경로 별칭 유지다. 소스 실시간 변경이나 대상 충돌이 있으면 이전 백업을 보존하고 일반 복사한다. 기존 `dis_`는 이름 규칙에 근거한 제한적 호환 예외이며 두 인스턴스 또는 외부 작업과의 경합은 아직 방지하지 않는다.

계획 → 저널 기록 → 이동 → 이전/새 경로 및 백업 식별 확인 → 매니페스트 확정 순이다. 저널에는 영역, 전후 경로, 세대·ID, 예상 충돌 상태를 남긴다. 연결이 끊기면 이전만 있으면 검증 뒤 재시도, 새 경로만 있고 ID 일치면 결과 확정, 둘 다 있거나 둘 다 없으면 데이터 확인 전까지 보류한다. `EXDEV` 등 실패 뒤 이전 데이터를 지우는 복사-삭제로 대체하지 않는다.

## 30일 보존 및 이력

처음 신뢰 가능한 삭제 관측을 UTC로 기록하고, 두 번째 완결 세대에서 재확인한 뒤에도 30×24시간이 지난 후에만 삭제 자격을 준다. 원본 파일 mtime·이력 이름 시각·작업 시작 시각에서 보존 기간을 소급하지 않는다. NAS 단절, 루트 바뀜, 권한 오류, 취소, 필터 변경, 일부 영역 미스캔은 삭제 증거로 채택하지 않는다.

같은 경로가 돌아오면 동일 객체의 삭제 후보는 해제한다. 다른 객체라면 삭제된 세대와 새 본체를 분리하며, 신뢰 가능한 세대 분리가 없으면 기존 데이터를 보류한다. 일반 rename은 기존 역사 버전을 새 위치로 옮길 경우에도 옛 경로→세대 별칭을 기록한다. 잘못된 rename 판정이 이전 경로 복구를 불가능하게 만들면 자동 재사용을 승인하지 않는다. remove는 현재의 버전 만료 계약을 유지한다. 향후 활성 보존 세대 안의 이력도 보호해야 한다면 삭제 제외 목록 또는 보존 전용 영역의 범위를 remove와 함께 합의한다.

A를 Go 경로에서 읽기 전용 관측으로 시작하고, 확인된 영역에서 B를 모의 실행한 뒤 작은 격리 공유에 적용한다. C는 변경 피드와 내구성 요구가 정량적으로 뒷받침된 경우에 검토한다. 전체 시간, 사용자 영역별 지연, 파일서버 SMB 메타데이터 호출·오류·재전송, 전송 바이트, CPU/RSS, 중복 바이트와 스풀 디스크 사용량을 같은 스냅샷·캐시 조건에서 따로 측정한다. 운영 수치는 현장 측정 후 기록한다.

## 전환 검증

1. 소규모 로컬 자료로 변경·오류·재실행을 확인한다. `dis_` 재사용, 두 이름 공존, 빈/비어 있지 않은 대상, 원본 미확인과 재실행을 구분한다.
2. 두 NAS의 격리 데이터에서 파일 내용 변경, 같은/다른 부모 rename, 폴더 삭제 뒤 동명 재생성, 재마운트·failover·캐시 지연·권한 거부, 백업 중 rename을 재현한다.
3. 대상 공유에서 열린 파일과 비어 있지 않은 대상 충돌, 이동 직전/직후 연결 끊김, 이력 실패와 재실행 복구를 확인한다.
4. 삭제 첫 관측과 불완전 세대, 30일 직전·경계·직후, 복구 경로 별칭을 시계 주입으로 시험한다.
5. 같은 입력에서 기본 스캔과 관측 실행을 비교해 추가 파일별 대상 조회가 없는지 측정한다. 복원 체크섬 불일치, 이력 손실, 불완전 영역의 삭제 자격이 하나라도 있으면 릴리스 보류다.
6. 요일별 전체 비교 검증에서는 시험 설정의 `Full Scan Day`를 실행 호스트의 현재 요일 및 다른 요일로 각각 지정한다. 원본의 세 시각이 기준 이전이고 대상 크기가 다른 기존 파일을 준비해, 다른 요일에는 건너뛰고 지정 요일에는 복사하는지 확인한다. 전체 비교 로그와 성공 후 저장된 실제 실행 시작 시각도 대조한다.

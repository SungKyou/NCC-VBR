# cifs 요건 정의서

기준일: 2026-11-17 / 원본: `cifs/vbr_cifs.c` 2.0672, `cifs/bs_common.c` / 양식: T01

## 1. 목적과 범위

- 하는 일: NAS의 한 디렉터리(원본)를 다른 디렉터리(대상)로 증분 백업한다. 바뀐 파일만 복사하고, 대상에 있던 이전 내용은 압축해 옆에 남긴다.
- 전환 범위에 드는 것: `vbr_cifs` 실행 파일의 모든 동작, 그리고 이 프로그램이 쓰는 `bs_common`의 기능(설정 읽기, 로그, 데몬화, 시각 문자열).
- 전환 범위에 들지 않는 것: `vbr_cifs`를 실행하는 관리 프로그램(설정의 `PROGRAM = vbr_mgr`로 추정), 이벤트를 받는 WEB 포털, NAS 마운트 자체. 받은 소스에 없다.

## 2. 이해관계자와 사용 방식

| 누가 | 어떻게 쓰는가 |
|---|---|
| 호출자(관리 프로그램 또는 스케줄러. 추정) | 백업 정책마다 `vbr_cifs 원본 대상 작업번호`를 실행한다. 프로그램은 바로 백그라운드로 분리된다 |
| WEB 포털 | 백업이 끝나면 완료 이벤트(`CIFSFIN00`)를 TCP로 받는다. 설정에 포털 주소가 있을 때만 |
| 운영자 | `server.log`, `transaction.log`로 결과를 본다 |
| `vbr_remove` | 이 프로그램이 남긴 이전 버전 파일(`-vbr-시각.zip`)을 보존 기간 뒤에 지운다 |

## 4. 비기능 요건

| 번호 | 분류 | 요건 | 근거 | 검증 |
|---|---|---|---|---|
| REQ-CIFS-N01 | 운영체제 | Linux에서 동작한다. Windows에서도 가능한 범위에서 동작한다 | 사용자 지시 5 | V0·V1을 두 운영체제에서 실행 |
| REQ-CIFS-N02 | 호환 | 실행 파일 이름, 인자 순서, 설정 파일 이름·섹션·키, 기준 시각 파일의 이름과 형식, 이전 버전 파일의 이름 규칙, 포털 전문 형식을 유지한다 | 원칙 2 | T-CIFS-P07, P10, U(portal) |
| REQ-CIFS-N03 | 호환 | 원본이 만든 기준 시각 파일과 대상 디렉터리를 그대로 이어받아 실행할 수 있다. 전환본이 만든 것을 원본이 이어받을 수도 있다 | 되돌리기 가능해야 함 | T-CIFS-P14~P19 |
| REQ-CIFS-N04 | 자료 보호 | 원본 디렉터리의 파일을 고치거나 지우지 않는다. 대상에서 지우는 것은 빈 `dis_X` 디렉터리와 압축에 실패한 이전 버전 파일뿐이다 | 원본 동작 | T-CIFS-U08, 정적 확인 |
| REQ-CIFS-N05 | 성능 | 원본보다 느리지 않다. 복사 버퍼는 640,000 byte, 작업자는 최대 50이다 | 원본 상수 | T-CIFS-L01 |
| REQ-CIFS-N06 | 운영 | 외부 라이브러리 없이 실행 파일 하나로 배포한다 | 표준 모델 목적 | 빌드 산출물 확인 |
| REQ-CIFS-N07 | 이식 | Java로 다시 옮길 수 있게 운영체제 의존을 한곳에 모으고 업무 규칙을 언어에 의존하지 않게 적는다 | 사용자 지시 6 | `common/02` 9장 |

## 5. 제약과 가정

| 번호 | 내용 | 종류 | 확인 상태 |
|---|---|---|---|
| 1 | 설정 항목이 `node_info.cfg`에 없으면 있는 것으로 본다. 개발 환경 파일에는 포털 주소가 주석 처리되어 있다 | 가정(사용자 지시 2) | 확인됨 |
| 2 | 프로그램은 실행한 디렉터리를 기준으로 설정·로그·기준 시각 파일을 찾는다 | 제약(원본 동작) | 확인됨 |
| 3 | 호출자가 종료 코드와 화면 출력을 쓰지 않는다 | 가정 | 미확인(Q-08) |
| 4 | 대상 디렉터리는 실행 전에 이미 있다(NAS가 마운트되어 있다) | 가정 | 미확인(Q-03) |
| 5 | 같은 원본·대상 쌍을 동시에 두 번 실행하지 않는다 | 가정(원본에 막는 장치 없음) | 미확인 |

## 6. 유지할 것과 바꿀 것

| 구분 | 내용 |
|---|---|
| 반드시 유지 | 명령행, 설정 키, 기준 시각 파일, 이전 버전 파일 이름, 변경 판단 규칙, 포털 전문, 로그의 날짜 형식과 주요 문구 |
| 바꿔도 되는 것 | 작업 분배 수단(System V 메시지 큐), 스레드 기동 방식, 상태 감시 방식, 안내용 로그 문구 |
| 바꿔야 하는 것 | 쓰기 실패를 알아채지 못하는 것, 오류가 있어도 기준 시각을 갱신하는 것, 대상이 없어도 진행하는 것 |

## 7. 용어

| 용어 | 뜻 |
|---|---|
| 원본 디렉터리 | 백업할 자료가 있는 디렉터리. 첫째 인자 |
| 대상 디렉터리 | 백업을 받는 디렉터리. 둘째 인자 |
| 기준 시각 | 직전에 끝난 실행의 시작 시각. 이 시각 이후 건드린 파일만 비교한다 |
| 이전 버전 파일 | 덮어쓰기 전에 대상의 내용을 압축해 남긴 `-vbr-시각.zip` 파일 |
| 작업 | 작업자 한 명이 끝까지 처리하는 디렉터리 하나 |
| 2단계 분할 | 크거나 파일이 많은 디렉터리를 한 단계 더 내려가 작업으로 나누는 것 |

# 설정 파일 `node_info.cfg` 명세

기준일: 2026-11-17 / 양식: T05의 설정 절

## 1. 위치

프로그램을 실행한 디렉터리의 `./node_info.cfg`다. 전환본은 `-home`으로 작업 디렉터리를, `-config`로 파일 경로를 바꿀 수 있다.

파일을 열 수 없으면 원본은 키마다 "찾지 못함"으로 처리하고 기본값으로 진행한다. 전환본도 같다. 로그에 `config file open error`를 남긴다.

## 2. 형식

```ini
# 주석
[섹션명]
키 = 값
키2		=	값 여러 개는 공백으로 구분
```

| 규칙 | 내용 | 원본과 전환본의 차이 |
|---|---|---|
| 섹션 | `[섹션명]`으로 시작하는 줄부터 다음 `[` 줄 전까지 | 없음 |
| 주석 | 앞뒤 공백을 없앤 뒤 `#`으로 시작하는 줄 | 없음 |
| 키와 값 | 첫 `=`의 앞이 키, 뒤가 값. 양쪽의 공백·탭을 없앤다 | 없음 |
| 대소문자 | 섹션명과 키는 구분한다 | 없음 |
| 중복 | 같은 섹션이나 같은 키가 여러 번 나오면 처음 것 | 없음 |
| 값이 없는 키 | `키 =` 또는 `=` 없는 줄. 값은 빈 문자열 | 없음 |
| 줄 길이 | 원본은 255자까지. 넘는 부분은 버려진다 | 전환본은 제한 없음 |
| 줄 끝 | LF, CRLF 모두 가능 | 없음 |
| 문자 인코딩 | 개발 환경 파일은 ASCII | 전환본은 UTF-8로 읽는다 |
| 읽는 시점 | 원본은 키를 찾을 때마다 파일을 다시 읽는다 | 전환본은 시작할 때 한 번 읽는다 |

키 이름에 공백과 괄호가 들어간다(`MAX Log size`, `WEB server(IP)`). 철자와 공백 수가 정확히 같아야 한다.

## 3. 섹션과 키

### `[VBR Manager]`

개발 환경 파일에 있는 섹션이다. `vbr_cifs`가 읽는다. 관리 데몬(`vbr_mgr`)의 섹션이기도 한 것으로 보인다.

| 키 | 개발 환경 값 | `vbr_cifs`가 읽는가 | 뜻 |
|---|---|---|---|
| `PORT-NO` | 10002 | 아니오 | 관리 데몬의 수신 포트(추정) |
| `PROGRAM` | vbr_mgr | 아니오 | 관리 데몬의 프로세스 이름(추정) |
| `Interval Time` | 30 | 아니오 | 추정: 상태 확인 주기(초) |
| `Retry Count` | 5 | 아니오 | 추정: 재시도 횟수 |
| `Mount Point` | /tmp/imsi/ | 아니오 | 추정: 백업 스토리지 마운트 위치 |
| `CPU Limit` | 50 | 아니오 | 추정: CPU 사용 한도(%) |
| `MAX Log size` | 100000000 | 예 | 로그 파일 교체 기준(byte) |
| `MAX Thread cnt` | 2 | 예 | 작업자 수 |
| `WEB server(IP)` | 주석 처리(192.168.1.113) | 예 | 포털 주소 |
| `WEB server(PORT)` | 주석 처리(10021) | 예 | 포털 포트 |
| `2ND SEARCH DIR` | /tmp/1/detail /tmp/1/detail1 | 예 | 2단계 분할 디렉터리 |
| `EXCLUSION DIR` | /tmp/1/a /tmp/2 … /tmp/28 (28개, 줄 길이 232자) | 예 | 백업 제외 디렉터리 |
| `QUEUE ID` | 30003 | 아니오(2.0671부터 전용 큐) | 이전 버전의 메시지 큐 키 |
| `Full Scan Day` | 2 | 예(2.068부터. 2.0672는 읽지 않음) | 첫 글자 0~6이 요일(0=일요일)이다. 그 요일에는 기준 시각 없이 전체를 비교한다. 없으면 일요일(안내 로그), 첫 글자가 0~6이 아니면 로그 없이 끈다(2.068과 같음). 개발 설정의 2는 화요일이다(C-CIFS-21) |

"추정"으로 적은 키는 받은 소스에서 읽는 곳을 찾지 못했다. 같은 이름의 키를 agent가 자기 섹션에서 읽는 것(`Interval Time`, `Retry Count`, `Mount Point`, `CPU Limit`)으로 미루어 적었다.

### `[File Remove (BATCH) for NCC-VBR]`

`vbr_remove`가 읽는다. 개발 환경 파일에 없다.

| 키 | 기본값 | 뜻 |
|---|---|---|
| `MAX Log size` | 50000000 | 로그 파일 교체 기준 |
| `Delete Mode` | LOG 모드 | `DELETE`이면 실제로 지운다 |
| `MAX Thread cnt` | 50 | 작업자 수 |
| `2ND SEARCH DIR` | 없음 | 2단계 분할 디렉터리(최대 10개) |
| `EXCLUSION DIR` | 없음 | 찾지 않을 디렉터리(최대 10개) |
| `QUEUE ID` | - | 원본만 읽는다. 메시지 큐 키 |

### `[VBR Agent for Xenserver]`

`vbr_agent`와 `dummy2`가 읽는다. 개발 환경 파일에 없다.

| 키 | 읽는 곳(`vbr_agent.c` 줄) | 뜻 |
|---|---|---|
| `PORT-NO` | 273 | 수신 포트 |
| `PROGRAM` | `bs_common.c` 수신 준비 | 중복 실행 판단에 쓰는 프로세스 이름 |
| `MAX Log size` | 231 | 로그 파일 교체 기준 |
| `WEB server(IP)`, `WEB server(PORT)` | 4538, 4546 | 포털 주소와 포트 |
| `Interval Time` | 951 | 상태 확인 주기 |
| `Retry Count` | 960 | 상태 확인 재시도 횟수 |
| `Mount Point` | 970 | 백업 스토리지 마운트 위치. `ALIVE_<호스트명>.chk` 파일을 만든다 |
| `CPU Limit` | 980 | 백업·복구 실행 때의 CPU 한도 |

agent의 키는 사전 분석에서 찾은 것이다. 전체 목록은 agent 전환 1단계에서 확정한다.

### `[Backup Task Manager for NCC-DaaS]`

개발 환경 파일에 있다. 세 서비스 가운데 읽는 것이 없다. 다른 제품의 섹션이다.

## 4. 전환에서 정한 것

- 형식과 키 이름을 바꾸지 않는다. 운영 중인 설정 파일을 그대로 쓴다.
- 새 키를 더하지 않았다. 전환본에서 더한 조정 항목은 명령행 옵션으로 두었다.
- 다른 형식(YAML 등)으로 바꾸는 것은 세 서비스 전환이 끝난 뒤에 따로 정한다. 지금 바꾸면 원본과 병행 운영할 때 설정 파일을 두 벌 관리해야 한다.
